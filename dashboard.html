    使用说明 · 扣费、Agent 接入与参数

    网页和自己的 Agent 使用同一套媒体 API、账号池与积分。下面的示例不会自动执行，也不会包含你的真实 Key；模型名、可用区域及规格以本页实时目录为准。

    扣费怎么算？
    媒体模型价格参考
    类型当前预算参考如何确认实际扣费
    生图 / 改图（WorkBuddy）未有实测记录时约 6 积分/张目录标为「估」时不是官方固定价；有实测后会标为「实测」。
    生图 / 改图（小浣熊）按账单实测，当前 20 积分/张单价取自积分账单里最近一笔「任务消耗 · 图片生成」，目录标「实测」。quality=high 会显著抬高上游 image tokens，但实测单价仍以账单为准。
    生视频缺少实测价时按 26 积分/秒预留预算，例如 5 秒约 130 积分这是引擎保守预算参考，不保证实际扣费上限。模型、分辨率、参考素材可能影响花费。

    优先看上方目录的最新价格。生成响应或完成的视频任务若带 credit，可记录为本次扣费；没返回时记为未知，不按 0 计算。图片签名 URL 约 24 小时失效，请及时保存。视频签名下载链接最多一小时有效，网关重启后需重新查询任务获取链接。

    媒体 API 工具封装建议
    建议封装的工具接口返回与处理
    generate_imagePOST /v1/images/generations同步返回图片，读取 data[0].url 或 data[0].b64_json。
    edit_imagePOST /v1/images/editsJSON 携带输入图片，返回修改后的图片。
    generate_videoPOST /v1/videosHTTP 202 返回任务 id，保存后轮询。
    get_video_statusGET /v1/videos/{id}queued → in_progress → completed / failed；完成取 url，失败读 error.message。
    cancel_videoPOST /v1/videos/{id}/cancel用于仍可取消的排队任务。上游已提交任务可能继续生成并计费，以响应为准。
    list_media_modelsGET /v1/media/models读取 data[] 中的模型、tags、价格与 videoGeneration；支持 ?tag= / ?realm=cn|intl 过滤。

    媒体模型通过独立接口调用，不进入聊天目录 /v1/models。只修改聊天 Base URL 不会自动让 Agent 获得媒体工具；需要 Agent 支持 HTTP 工具、自定义工具或对应的 MCP 适配。隐藏模型会被拒绝；省略 model 时只选当前出口可见且支持目标操作的模型。

    默认入口仅限本机。Docker 内的 127.0.0.1 是容器自身，远程 Agent 也无法直接访问本机回环地址；当前示例适用于运行在宿主机的 Agent。视频返回的签名下载 url 可直接使用，无需把网关 Key 放入 URL。

    生图 / 改图：可用参数

    两个平台的约束不一样，下表按平台分开写。媒体页的尺寸下拉会跟着当前模型切换，不会给出必然失败的尺寸。

    生图和改图参数
    参数是否必填取值与约束
    model建议指定如 raccoon/gpt-image-2、workbuddy/hunyuan-image-alpha；改图用支持 image-to-image 的模型，如 workbuddy/hunyuan-image-alpha-edit。
    prompt必填非空提示词。
    size可选格式「宽x高」。小浣熊：最长边 ≤ 3840 且总像素 ≤ 8,294,400，方形最多 2880x2880，不传则上游自选比例（实测 1254x1254 或 1402x1122，不固定）。WorkBuddy：总像素 ≤ 4,194,304，2560x1600 是实测边界，超了上游直接拒绝且不降级。
    quality可选仅小浣熊 gpt-image-2 生效，取 low / medium / high。不传时上游默认 low；high 会让 image tokens 涨 30 倍以上（1024 档 229 → 7050），要出好图必须显式指定。WorkBuddy 引擎忽略此参数。
    n可选一次只支持 1 张，默认 1。小浣熊上游收字符串会报 400，网关已剥掉该字段；n > 1 直接拒绝。
    response_format可选url（默认）或 b64_json。转码失败时可能退回 URL，请检查实际返回字段。
    image改图必填只在 /v1/images/edits 使用。小浣熊只收 data:image/...;base64,...，传外链 URL 会被上游 400 拒绝；WorkBuddy 还接受公网 http(s) 图片 URL。两者都支持字符串数组传多图。

    改图当前使用 JSON，不支持 multipart 文件上传或本地文件路径（发 multipart 会被网关直接 400）。图片比例由 size 控制；style、seed、negative_prompt、input_fidelity 等图片参数当前未实现，不应依赖其生效。

    生视频：可用参数与模型限制
    生视频参数与模型限制
    参数是否必填取值与约束
    model建议指定如 workbuddy/minimax-video-h3。模型需在当前媒体出口可用且未隐藏。
    prompt必填非空；当前 Kling 最多 2500 字符，MiniMax 最多 2000 字符。
    seconds可选整数秒，默认 5。当前 Kling 为 3–15 秒，MiniMax 为 4–15 秒；引擎设置可进一步限制。
    resolution可选Kling：720P / 1080P / 4K，默认 720P；MiniMax：768P / 2K，默认 768P。
    aspect_ratio可选仅文生视频生效，图生视频由输入图决定比例。Kling：16:9 / 9:16 / 1:1；MiniMax 还支持 adaptive / 21:9 / 4:3 / 3:4。
    size可选如 1280x720，推导分辨率及文生视频比例；显式 resolution、aspect_ratio 优先。不支持的分辨率/比例可能回落默认值。
    negative_prompt可选负面提示词，长度上限同 prompt。
    enable_audio可选布尔值；当前默认 true。Kling 可开关，MiniMax 音频常开，false 无法关闭。
    image / input_reference可选首帧，传单个公网图片 URL 或 data URL 字符串。input_reference 是别名，不使用数组/文件对象。
    last_image可选尾帧，与首帧配合使用。当前首尾帧由 Kling / MiniMax 模型声明支持。
    reference_images可选参考图数组，别名 images。可用字符串数组，或 {"image_url":"..."} / {"url":"..."} 对象数组。
    reference_videos可选参考视频数组，字符串或 {"video_url":"..."} 对象。
    reference_audios可选参考音频数组，字符串或 {"audio_url":"..."} 对象。
    wait可选使用 ?wait=1 或 JSON "wait":"1" 等待，完成后仍可能返回 202；排队或超时会返回当前状态。Agent 建议提交后轮询。

    Kling 不支持参考素材数组，首尾帧另算。MiniMax 参考图最多 9、视频最多 3、音频最多 3，合计最多 12；首尾帧与参考素材不能混用。参考音频需同时有视觉素材，最终以目录和上游校验为准。参考素材用公网 URL 或受支持的 data URL，不使用本地路径。

    seed、fps、自定义 watermark 等视频参数当前未实现。参数放在 JSON 顶层，不需要自行构造 extra_parameters。
